# ccsmoni（ししすもに）計画書

> Claude Code の利用状況モニター — 複数の Claude アカウントの利用状況（5時間枠・週間枠）を定期的に取得・記録し、**推移**をダッシュボードで見られるようにするツール。
> 状態: **実装済み**。この文書は開発時の計画で、経緯の記録として残している。その後のダッシュボードの作り直しは [UI-V2.md](UI-V2.md)、レビューは [REVIEW.md](REVIEW.md)
> 更新: 2026-10-27

> **機密の扱い**: エイリアス名・パス・ホスト名・アカウント情報などの実環境情報は、リポジトリに入れない。この計画書では一般化した名前（`acct-a` など）で書く。実環境の情報は git 管理外の `local/` に置く（§7.3）。

---

## 1. 背景と目的

- ユーザーは複数の Claude アカウントを使い分けている。アカウントごとに、環境変数 `CLAUDE_CONFIG_DIR`（Claude Code の設定フォルダの場所）を切り替えるシェル関数を用意している。
- 残り枠は `/usage` を1つずつ叩かないとわからない。いつ・どのアカウントで・どれくらい使っているかの**推移**がまったく残らない。
- **目的**: 全アカウントの使用率の**推移**を記録して見られるようにする。今の残り枠・リセット時刻・ログイン状態もひと目でわかるようにする。ログイン切れは、その画面から直せるようにする。

## 2. ユースケース（スコープを決める軸）

| # | 優先 | 場面 | 期待する体験 |
|---|---|------|--------------|
| U1 | ★最優先 | 「最近どのアカウントをどれくらい使っているか」を見たい | 推移のグラフで、全アカウントの5h枠・週間枠の使用率が時系列で並ぶ。リセットの位置がわかる。期間（24h / 7日 / 30日）を切り替えられる。週ごとのピーク使用率も見られる |
| U2 | 高 | 今の状況を確認したい | 現在値のカード（使用率、リセットまでの残り時間、ペース）。「週間リセットが近いのに余っている＝使わないと損」のヒント |
| U3 | 高 | ログインが切れている | カードに「ログイン切れ」と出る。［ログイン］を押すと、Web UI 上でログインの流れを最後まで進められる（§5） |
| U4 | 高 | 監視するアカウントや取得間隔を変えたい | Web UI の設定画面で、追加・編集・無効化・並べ替え・アカウントごとの取得間隔を変えられる。保存するとすぐ反映される。設定ファイルを直接編集しても反映される |
| U5 | 中 | 起動したい | `ccsmoni.bat` をダブルクリックすると起動してブラウザが開く。起動中なら、ブラウザを開くだけにする |

### やらないこと（MVP）

- **非公開APIの利用、ccsmoni によるトークン（ログイン情報）の読み取り・保存・中継**（§3.3。規約上の理由で、将来も原則やらない）
- 通知、タスクスケジューラへの登録、タスクトレイ常駐（§10 の将来候補）
- 「次はどのアカウントを使うか」のおすすめ表示（優先度を下げた。§10）
- `/usage` 下部にある「What's contributing」欄の構造化（raw テキストには残す）
- 複数 PC にまたがる集約

## 3. 調査結果（2026-10-27 に実機で確認）

### 3.1 アカウントの実体

- シェル関数の中身は「`CLAUDE_CONFIG_DIR` を設定して `claude` を呼ぶ」だけ。
  → **ccsmoni はシェル関数を経由しない**。設定には「ID・表示名・config ディレクトリ」を持ち、子プロセスごとに環境変数を設定して `claude.exe` を引数配列で直接起動する。

### 3.2 使う CLI コマンド

| コマンド | 用途 | 確認できたこと |
|---|---|---|
| `claude auth status --json` | ログイン状態の判定 | **約0.3秒**。`loggedIn`、`authMethod`、`subscriptionType`、`orgId` などが JSON で返る。ログインが切れていると `loggedIn:false` で、終了コードは 1 |
| `claude -p "/usage" --output-format json --no-session-persistence` | 使用率の取得 | ローカルのコマンドとして処理され、**モデルは呼ばれない**（料金 0、2〜4秒）。結果のテキストは `result` に入る |
| `claude auth login`（端末につながずに起動した場合） | ログイン | ブラウザを開いたうえで、**ログイン用URLを標準出力に表示**し、`Paste code here if prompted >` で**標準入力からコードを待つ**（リダイレクト先は Anthropic が用意したコード表示ページ） |

`/usage` の出力パターン（実サンプルは `local/research/samples/`。テスト用には機密を除いたものを作り直す）:

| パターン | 特徴 |
|---|---|
| 正常 | `Current session: 6% used · resets Oct 27, 4:20am (Asia/Tokyo)` と `Current week (all models): …` |
| モデル別の週間枠あり | `Current week (<モデル名>): 15% used · …` が追加される |
| 枠が始まっていない | `Current session: 0% used` だけで、resets も週間の行もない |
| ログイン切れ | `Total cost: $0.0000 …` という API 課金用の表示になる（終了コードは 0） |

落とし穴（すべて実際に踏んだもの）:
- Git Bash を経由すると `/usage` がパスに書き換えられ、**通常のプロンプトとしてモデルに送信される**。→ シェルを介さず、引数配列で起動する。
- `--bare` を付けると認証情報が読まれず、ログイン切れと同じ表示になる。→ 使わない。
- `-p` は既定でセッションを保存する。→ `--no-session-persistence` を付ける。
- 終了コードでは成否を判定できない。→ `auth status` と出力の中身で判定する。
- リセット時刻は表示の丸めで揺れる（`4:20am` ↔ `4:19am`）。年は表示されない。タイムゾーンは IANA 名が括弧書きで付く。

### 3.3 非公開API（`/api/oauth/usage`）を使わない理由

`/usage` の内部で使われている API に、トークンを付けて直接アクセスできることは確認した。ただし **Anthropic 公式の [Legal and compliance](https://code.claude.com/docs/en/legal-and-compliance)** には、次のように書かれている。
- OAuth 認証は「Claude Code やその他の Anthropic 純正アプリでの通常の利用」のためのもの。
- 「developers may not collect, store, or intermediate Claude.ai credentials or session tokens — sign-in to a Claude account must complete through Anthropic's own flow」（開発者は Claude.ai の認証情報やセッショントークンを収集・保存・中継してはならない。ログインは Anthropic 自身の手順で完了させること）
- 違反には予告なく対処することがある。2026年初めには、Claude Code 以外からのサブスクリプショントークンの利用をサーバー側で遮断した例も報道されている。

→ 自分で使う読み取り専用の API 呼び出しでも、**トークンをファイルから抜き出して Claude Code 以外から使う行為は、この規定に正面から当たる**。アカウント停止のリスクは低いかもしれないが、ゼロとは言えず、得られる情報（小数の使用率、追加課金枠）とは釣り合わない。**採用しない**。
一方で、**改変していない `claude` CLI を、その CLI 自身の機能（`-p` の非対話モード、`auth`）で動かすのは、公式に用意された使い方**の範囲になる。ccsmoni はトークンに一切触れない。

## 4. 全体像

```
 ┌───────────────── ccsmoni serve（常駐プロセス 1つ） ─────────────────┐
 │                                                                      │
 │  ConfigService ◀── Web の設定画面（保存）                            │
 │   (TOML が唯一の正) ◀── ファイルの直接編集（変更を検知）             │
 │        │ 変更を通知                                                   │
 │        ▼                                                             │
 │  Scheduler ── アカウントごとの間隔 / 今すぐ更新 / 同時実行の制限     │
 │        ▼                                                             │
 │  Probe（取得方法 = Source + Parser の組。差し替えられる）            │
 │    └ CliUsageSource : claude auth status --json で確認 →             │
 │                       claude -p /usage --output-format json …        │
 │        ▼ RawResult（raw テキスト・終了コード・所要時間）             │
 │    UsageTextParser（純粋関数）→ Reading                              │
 │        ▼                                                             │
 │  Store（SQLite）: snapshots（raw も保存）/ limits / windows（枠の識別）│
 │        ▼                                                             │
 │  Insights（純粋関数）: ペース・枯渇の予測・「使わないと損」・週ピーク│
 │        ▼                                                             │
 │  HTTP: JSON API + 静的ダッシュボード（ループバックのみ・Host を確認）│
 │  LoginService: claude auth login のコンソールを開き、完了を監視      │
 └──────────────────────────────────────────────────────────────────────┘
        ▲ tailscale serve で tailnet 内（PC・スマホ）にだけ公開
  ccsmoni.bat: ccsmoni serve を呼ぶだけ（起動済みなら serve がブラウザを開いて終わる）
```

### 4.1 取得方法の抽象化（D1 の決定を受けて）

抽象化は「差し替える単位」だけに絞り、層を増やしすぎない。

```python
class Source(Protocol):            # どう取ってくるか
    kind: str                      # "cli-usage" など
    def fetch(self, account: Account) -> RawResult: ...

class Parser(Protocol):            # 取ってきたものをどう読むか
    def parse(self, raw: RawResult, account_id: str) -> Reading: ...   # raw と id だけから作る（reparse のため）

# Probe = Source + Parser の組。設定の probe = "cli-usage" で選ぶ。
# 将来、別の取得方法を足すときは、Probe を1つ登録するだけでよい。
```

- **共通データ形式 `Reading`**（下流はこれだけを見る）
  ```
  Reading { account_id, taken_at(UTC), probe, status, message?,
            limits: [{ kind, label, percent, resets_at?(UTC) }] }
  kind:   session | weekly_all | weekly_model:<name>
  status: ok | logged_out | error | timeout | parse_error
  ```
- **raw を必ず保存する**: パーサーを直したり形式が変わったりしても、`ccsmoni reparse` で過去分を作り直せる。
- **1回の取得の流れ**: `auth status`（0.3秒）でログインを確認する → ログインしていれば `/usage` → パース。ログイン切れを、テキストの見た目ではなく確かな情報で判定できる。

### 4.2 推移を正しく描くための工夫

- **枠の識別**: 同じ `(account, kind)` の直近の枠と `resets_at` が ±15 分以内なら同じ枠とする（表示の丸めによる揺れを吸収する）。
  ただし `resets_at` が同じでも、直前の値から使用率が **10 ポイント以上**下がったら新しい枠とする（リセットの取りこぼしを防ぐ）。
  許容幅とポイントは `model.py` の定数（`WINDOW_TOLERANCE_SEC`・`WINDOW_DROP_POINTS`）で、保存（store）と分析（insights）が共有する。
  取得時刻の順に決定的に割り当てるので、`reparse` でも同じ結果になる。
- **リセットの検出**: 使用率が下がった、または枠の ID が変わったら「リセットされた」とみなす。グラフは枠ごとに線を切り、リセットの位置に縦線を引く（ノコギリ状の5h枠が、つながった線に見えないようにする）。
- **年の補完**: 取得時刻から見て「−1日〜+8日」の範囲に入る年を選ぶ。
- **取得の抜けを見せる**: PC がスリープしていた間などデータがない区間は、線を補間せずに空白で示す（嘘の線を引かない）。

### 4.3 パーサーの判定順

1. `auth status` が `loggedIn:false` → `logged_out`（`/usage` は実行しない）
2. `Current session:` / `Current week (…)` の行が1つ以上ある → `ok`
3. `Total cost:` のコスト表示 → `logged_out`（`auth status` と食い違った場合の保険）
4. タイムアウト → `timeout`／起動失敗 → `error`
5. それ以外 → `parse_error`（raw を残し、UI に「出力形式が変わった可能性」と出す）

## 5. ログイン切れへの対処（U3）

### 5.1 検証でわかったこと

`claude auth login` を端末につながずに起動すると、ログイン用URLを出力し、**標準入力からコードを受け付ける**。リダイレクト先は Anthropic のコード表示ページ（localhost ではない）なので、**スマホでログインしても成立する**。

### 5.2 採用する方式（D6: A のみ）

**PC 上にログイン用のコンソールを開く方式だけを採用する**。スマホからできるようにしても、スマホ側のブラウザでログイン用のアカウントにログインしていないことが多い。ログインは PC で行えば十分。

1. カードの［ログイン］を押す → ccsmoni が `CLAUDE_CONFIG_DIR` を設定した `claude auth login` を、**新しいコンソールウィンドウ**（`CREATE_NEW_CONSOLE`）で起動する。ブラウザも PC 上で開く。ccsmoni はコードやトークンに一切触れない。
2. カードは「ログイン待ち…」になる。ccsmoni は数秒おきに `auth status --json` を確認する（最大 10 分）。
3. `loggedIn:true` になったら、`orgId` を前回ログインしていたときの値（ローカルの DB）と比べる。違えば「別のアカウントでログインした可能性」と警告する。そのあとすぐ再取得し、カードを ok に戻す。
4. PC 以外（tailnet 経由のスマホなど）から押された場合も PC 上で起動するので、画面には「PC 側にログイン画面を開きました」と表示する。コピー用のコマンド（`<起動コマンド>` → `/login`）も常に表示する。

却下した案: Web UI でコードを受け渡す方式（規約上グレーで、スマホでの利点も小さい）。

## 6. ダッシュボードの UX

画面は **「推移」（トップ）／「設定」** の2つ。ヘッダーで切り替える。

### 6.1 推移画面（トップ、U1・U2）

- **ヘッダー**: 最終更新「2分前」・次回の更新予定・［今すぐ更新］（処理中はスピナー、完了すると時刻が変わる）。
- **現在値の帯**（アカウントごとのコンパクトなカード）: 表示名・プランのバッジ・5h と週間のミニバー・リセットまでの残り時間・状態チップ（`OK`／`ログイン切れ［ログイン］`／`取得失敗`／`データが古い`）。カードを押すと、そのアカウントがグラフで強調表示される（もう一度押すと元に戻る）。
- **推移グラフ（主役）**
  - 既定は「週間枠」の重ね合わせ（全アカウントを1枚に、アカウントごとに色分け）。［週間 / 5h］の切り替え、［24h / 7日 / 30日］の期間切り替え。
  - **凡例を押すと、そのアカウントの表示／非表示が切り替わる**（もう一度押すと戻る）。凡例をダブルクリック（スマホでは長押し）すると「そのアカウントだけ表示」になる。表示状態はブラウザに保存し、次に開いたときも維持する。現在値のカードを押したときの強調表示も、この凡例の状態と連動させる。
  - アカウントごとに分けて並べる表示（small multiples）にも切り替えられる。1行1アカウントで、週間を線、5h を薄い面にし、リセット位置に縦線を引く。重ね合わせると見にくいときのため。
  - ホバー／タップで、その時点の全アカウントの値をツールチップに出す。
- **週ごとのピーク表**: アカウント × 過去の週で、各週の最大使用率をヒートマップ風に表示する（「この垢は毎週ほぼ使い切っている」がわかり、プランを考える材料になる）。
- **気の利くヒント**（カードの下に1行）: 「週間リセットまで 20h・残り 36% → 使わないと損」「このペースだと 金 14:00 に上限」。
- ダークモード、スマホ幅への対応。色のしきい値（警告・危険）は設定で変えられる。

### 6.2 設定画面（U4）

- アカウント一覧（ドラッグで並べ替え、有効／無効の切り替え）。行を押すと編集フォームが開く。
- 項目: 表示名、config ディレクトリ、起動コマンド（コピー・案内用）、色、**取得間隔（アカウントごと。空欄なら全体の既定値）**。
- ［接続テスト］ボタン: 保存する前に、そのアカウントで1回だけ取得して結果（ok／ログイン切れ／失敗）をその場に表示する。
- **未登録アカウントの検出**: 既知の設定フォルダの親ディレクトリ（設定で指定）を走査し、未登録の候補を「＋追加」で一覧に出す。
- 全体設定: 既定の取得間隔、タイムアウト、同時実行数、色のしきい値。
- 状態表示: 「保存済み」「未保存の変更あり」「ファイルが外部で変更されました［読み込み直す］」。

## 7. 設定・データ・機密

### 7.1 設定の実装（D5: UI での編集を MVP に含める）

**TOML ファイルを唯一の正とし、UI はその編集画面にする**（推奨）。

- `ConfigService` が「読み込み → 検証（pydantic のモデル）→ 保存」を一手に引き受ける。ファイルを直接編集した場合も、UI から保存した場合も、**同じ検証を通る**。
- 書き込みは `tomlkit` で行い、**コメントや並び順を保つ**（手で書いたメモが UI からの保存で消えない）。一時ファイルに書いてから置き換える（アトミックな書き込み）。
- **競合の検出**: UI は読み込んだときのファイルのハッシュを持っておき、保存時に一致しなければ拒否して「外部で変更されました」と出す（楽観ロック）。
- 変更を検知したら（ファイルの内容のハッシュを数秒おきに確認）、再読み込みして Scheduler に通知する。再起動はいらない。
  ファイルが壊れた・空になった・消えたときは、最後に有効だった設定で動き続け、画面に理由を出す。
- 保存では、書き出す予定の TOML 全体を読み込みと同じ検証に通してから置き換える（既知のセクションにあるスキーマ外のキーは取り除く）。
  TOML の構文エラーのファイルは `config.toml.broken-<日時>` に退避してから書き出し直す。
- `collector.claude_path`・`server.host`・`server.port` はファイルでだけ編集する（UI では表示だけ。任意のコマンドの実行・外部への公開を防ぐため）。
- アカウントの `id` は履歴のキーなので変更しない。表示名は自由に変えてよい。アカウントを削除しても履歴は残し、「アーカイブ」として扱う。
- 却下した案: 設定を DB に持つ（正が2つになる）、TOML をそのまま編集する欄だけにする（簡単だが使いにくい）。

設定ファイルの例（実ファイルは git 管理外）:

```toml
[collector]
default_interval_minutes = 10
timeout_seconds = 30                  # 1回の取得（auth status + /usage）全体の締め切り
concurrency = 2
claude_path = "claude"                # claude 本体（stem が claude のものだけ。ファイルでだけ編集する）
discover_roots = ["~/claude-configs"] # 未登録アカウントを探す場所（複数可）
discover_depth = 2

[server]
host = "127.0.0.1"                    # ループバックのみ（127.0.0.1 / ::1 / localhost）
port = 8484
allowed_hosts = []                    # Host として受け付ける追加の名前（MagicDNS の短い名前など。*.ts.net は常に可）

[ui]
warn_percent = 70
danger_percent = 90

[[accounts]]
id = "acct-a"
label = "個人"
config_dir = "~/claude-configs/acct-a"
launch_command = "claude-acct-a"
color = "#4f8cff"
interval_minutes = 5                  # アカウントごとに上書き（D4）
enabled = true
```

### 7.2 データ

- 置き場所: `%LOCALAPPDATA%\ccsmoni\`（`config.toml`、`ccsmoni.db`）。環境変数 `CCSMONI_HOME` で変更できる。**リポジトリの外**に置く。
- テーブル: `snapshots`（取得1回分。raw・状態・所要時間・CLI のバージョン）、`limits`（枠ごとの値。枠の ID 付き）、`account_meta`（直近の orgId やプランなど。ログイン後の確認に使う）。

### 7.3 機密の扱い（リポジトリのルール）

- 機密情報: エイリアス名、パス、ユーザー名、ホスト名・IP、org 名・ID、メールアドレス、実際の出力に含まれるスキル名など。
- `local/`（git 管理外）に置くもの: 実出力のサンプル、`local/secret-words.txt`（禁止語のリスト）、実環境のメモ。
- **テスト用のサンプル**は、実サンプルから機密を除いて作り直したものを `tests/fixtures/` に置く。
- **コミット前の自動チェック**: `scripts/check_secrets.py` が、ステージされた差分に禁止語が含まれていないかを調べる。git の pre-commit フックに登録する（人の注意力に頼らず、仕組みで防ぐ）。
- 初回コミットの前に、既存の文書（この計画書を含む）から実環境の記述を除き、チェックに通ることを確認する。

## 8. 技術選定

| 領域 | 採用 | 理由 |
|---|---|---|
| 言語・管理 | Python 3.13 + uv | 子プロセス・SQLite・タイムゾーンが標準ライブラリで足りる |
| Web | FastAPI + uvicorn | JSON API と静的ファイルの配信だけなので軽い |
| 設定 | tomlkit + pydantic | コメントを保ったまま書き戻せる。読み込みと UI からの保存で、同じスキーマ検証を使える |
| DB | SQLite（WAL モード） | 1台・単一プロセスで十分 |
| スケジューラ | asyncio のループ（アプリ内） | 常駐プロセス1つで済む |
| フロント | ビルド不要の HTML/CSS/JS + uPlot（同梱） | ページ2枚の規模に見合う。時系列のグラフが軽くて速い |
| タイムゾーン | zoneinfo + tzdata | Windows には IANA のデータベースがないため |
| 起動 | `ccsmoni.bat` | 下記 |
| 公開 | `tailscale serve --bg --https=<port> http://127.0.0.1:<port>`（専用の HTTPS ポート。443 の既存の公開設定と共存できる。初回だけ設定すれば保持される） | アプリは 127.0.0.1 にだけ bind する |

**`ccsmoni.bat` の動作**: 毎回 `uv run --project <bat の場所> ccsmoni serve` を呼ぶだけ。判定は serve 側が行う: ① 設定のポートの `GET /api/health` が ccsmoni なら、ブラウザを開いて終了する。別のサービスがポートを使っていれば、その旨を出して終了する。② 起動していなければ常駐し、準備ができたらブラウザを開く。ウィンドウは開いたままにする（閉じれば止まる。わかりやすさを優先）。③ 初回だけ `--setup-tailscale` で `ccsmoni tailscale-setup`（設定のポートを専用の HTTPS ポートとして `tailscale serve --bg --https=<port>` で公開する。既存の設定を読み、同じポートが別の転送先に使われていれば上書きせずに止める）を呼ぶ。設定ファイルに誤りがあれば、serve はどのファイルのどの項目かを日本語で出して終了コード 2 で止まる。

**最低限の防御**: すべてのリクエストで Host ヘッダーを許可リスト（ループバック・`*.ts.net`・`server.allowed_hosts`）と照合する（DNS rebinding 対策）。POST/PUT は Origin も確認する（許可リストにあり、かつ Host と一致すること。`X-Forwarded-Host` は信頼しない）。設定から起動できるのは `claude` 本体だけにし、その設定（と host・port）は Web から変えられないようにする（任意のコマンドは実行させない）。読み取り API には認証を付けない（個人用の tailnet 内だけに公開する前提）。
