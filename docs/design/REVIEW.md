# UI v2 の独立レビューと対処（2026-10-27）

レビュー対象はコミット `03db250`（UI v2 の初版）で、2つの目で見た。
- R1: Codex CLI
- R2: 新しく立てたサブエージェント（デモを実際に操作し、スクリーンショットで確かめた）

指摘は合わせて must 6・should 16・could 9 件。**すべて対処した**（コミット `ed3938e`）。主なものは次のとおり。

| 区分 | 指摘 | 対処 |
|---|---|---|
| must | 履歴の取得要求が、tail の更新で上書きされて失われる（R1） | 取得の待ち行列を分け、取得が終わるたびに今の表示範囲を取りに行く |
| must | リサイズや重ねる表示での起動時に、canvas の座標がずれる・5h レーンが切れる（R1） | ResizeObserver ですべての Plot を測り直し、状態の更新時にレーンの高さを決め直す |
| must | ログイン切れのとき、今週のピークが「前週」と表示される（R2） | 進行中かどうかを resets_at と今の時刻で判定する |
| must | ページを前から詰めると「6＋1」のように1枚だけの巨大なタイルができる（R2） | 均等に配る（7件・上限6 → 4＋3） |
| must | ドラッグ中の Esc が効かない（R2） | interact に cancel を加えた |
| should | 操作に気づけない（R2） | 1回だけのトースト、［?］のヘルプ、ストリップの印 |
| should | 全体の中のどこを見ているかがわからない（R2 の提案） | ストリップを全期間のミニマップにし、枠のドラッグで移動・範囲の変更ができる |

残った課題（今回は対処しない）
- ミニマップのために、最大 120 日分の履歴を一度だけ読み込む。履歴が長いと数 MB になる。間引いたデータを返す API があればよい。
- ヒントがどの枠についてのものか（limit の種類）をサーバーが返していないので、ヒントを押したときの拡大先は推定になっている。
